# Codex Mobile

通过手机阅读官方 Codex 本机聊天、发送文字、创建聊天和查看用量。从 v0.3.21 起，Windows 版通过官方桌面原生入口支持手机文字发送和新建聊天。电脑端为 Tauri 2 应用，Rust 提供连接、历史、通知、用量和版本更新，手机网页使用 Vue。

## 启动

目标平台为 Windows x64 和 Apple 芯片 macOS，两个程序使用同一个系统账号。Windows 版已验证默认 ~/.codex 的官方桌面文字发送、新建及状态同步；macOS 与其他 Codex 目录仍为历史只读。iPhone 真机和完整控制功能未全部验收。

### 使用桌面安装包

仓库公开后，源码与已发布的安装包均可直接访问。从 [GitHub Releases](https://github.com/J-Smile/codex-mobile/releases) 下载对应版本：

| 平台 | 安装方式 | 免安装方式 |
| --- | --- | --- |
| Windows x64 | 运行 windows-x64-setup.exe，安装后从开始菜单打开 Codex Mobile | 完整解压 windows-x64.zip，双击 Codex Mobile.exe |
| macOS Apple 芯片 | 打开 macos-arm64-setup.dmg，将 Codex Mobile 放入应用程序 | 完整解压 macos-arm64.zip，打开 Codex Mobile.app |

运行包包含手机网页和 Rust 程序，无需安装 Node.js、Rust 或 C++ 开发工具。Windows 界面使用 WebView2；安装程序会处理缺失的 WebView2 运行环境。

桌面首页提供“手机扫码连接”、已配对手机和连接状态。局域网二维码和密钥位于“设置 → 连接与维护 → 局域网连接”，本地服务默认端口为 4319。跨网络请使用下方的[云连接](#在-vps-部署云连接)。关闭窗口后程序留在托盘，从托盘选择“退出连接服务”才会关闭手机服务。官方 Codex 继续执行已有任务。

桌面“设置 → 通用”的“开机启动”开关控制登录系统后是否自动运行 Codex Mobile，状态直接读取系统启动项；开机启动时留在托盘，手动点击桌面快捷方式或托盘图标才显示窗口。“设置 → 连接与维护 → 服务设置”里的“打开程序时自动启动连接服务”单独控制是否启动手机网页服务。两项都开启后，登录电脑即可提供手机访问；历史阅读不等于实时控制。

第一次从旧 Node 版本切换时，先正常关闭旧的 4319 连接服务，再打开桌面版。端口被占用时窗口会显示启动失败，不会接管或结束原服务。已有配对密钥、会话、图片、通知和用量数据继续使用用户目录下的 .codex-mobile；聊天仍由官方 Codex 保存。

打开 Codex Mobile 后可启动手机服务并读取已保存历史。有官方桌面保存的本机项目时，手机「全部项目」会按原有项目归属展示聊天。Windows 版连接当前官方桌面 App Tools 通道后开放文字控制；连接失败仍保留历史与草稿，不把网页在线当成官方同步就绪。“重新连接”复用原生探测，不新建或借用控制聊天。“打开 Codex”使用官方原始启动路径，不注入 FORCE_CLI，不接管旧运行时，不清理正在执行的任务。状态查询不会启动官方桌面或创建聊天。

### 软件更新

从 v0.3.26 起，安装版直接读取公开仓库的正式 Release，无需 GitHub token。桌面点击“检查更新”，或在手机“设置 → 在线升级”中点击“立即升级”。更新来源默认收起。

遇到 GitHub 请求限额时，可在“更新来源”配置可选 token。生成 fine-grained personal access token，仅选择 J-Smile/codex-mobile 仓库，并授予 Contents: read。验证成功后只保存在电脑上，界面不回显，浏览器不持久化。旧 token 失效或无权读取新仓库时，本轮检查和下载自动改用匿名请求；移除 token 后仍可更新。

旧版客户端仍使用旧升级逻辑；无法检查更新时，从 GitHub Releases 手动安装一次 v0.3.26 或更高版本。同版本重新打包不会触发自动升级，后续修复使用递增版本号。

手机“设置 → 在线升级”同时显示运行中的 Codex Mobile 版本和当前官方连接的版本。App Server 版本来自连接握手；原生 App Tools 没有提供版本时显示“版本未知”，不冒充 App Server 版本。断开时显示“未连接”，重新打开面板会读取最新状态。

token 位于 Windows 的 %USERPROFILE%/.codex-mobile/github-token 或 macOS 的 ~/.codex-mobile/github-token。环境变量 CODEX_MOBILE_GITHUB_TOKEN 优先；使用环境变量时界面会显示来源并禁止覆盖。

安装包每 15 分钟检查正式 Release。Rust 更新器下载对应平台的 ZIP、校验 SHA-256 和运行资源，等待在途请求完成或记录未知结果后切换桌面版本。新版报告服务就绪后才保存安装记录；启动失败时仅可恢复同样声明新连接边界的版本并显示原因，同一失败版本等待后续版本。电脑端也可以手动检查和安装。

在手机打开“设置 → 在线升级”，点一次“立即升级”即可回到聊天。电脑在后台检查、下载并校验新版，切换时连接会短暂中断，恢复后手机自动重连，在编辑或发送结束后刷新并恢复当前聊天和草稿。手机发起升级需要支持该入口的桌面安装版。

更新资源保存在 .codex-mobile/updates/native。Windows 后续在线升级沿用桌面程序的启动路径，可以继续使用已有的防火墙放行规则。首次开放局域网访问时按 Windows 提示授权，从旧版首次迁入时也可能需要授权一次。原快捷方式会进入最近成功安装的版本。CODEX_MOBILE_AUTO_UPDATE=0 暂停自动检查；源码运行不安装 Release。旧 Node 更新器需要手动安装一次此桌面版。更新只切换 Codex Mobile，不会重启官方 Codex 或共享运行时。

### 从源码启动

开发需要 Node.js 24+、Rust stable。Windows 另需 Visual Studio Build Tools 的“使用 C++ 的桌面开发”（MSVC 与 Windows SDK）和 WebView2；macOS 需要 Xcode Command Line Tools。

    git clone https://github.com/J-Smile/codex-mobile.git
    cd codex-mobile
    npm ci
    npm start

npm start / npm run dev 会构建手机网页和 Rust 组件，再启动 Tauri 开发窗口。源码目录的“启动.cmd”与“启动.command”也使用这个入口。只调试手机服务时，运行 npm run start:bridge；另开终端执行 npm run dev:mobile 可使用 Vite 前端热更新。

正式安装程序和更新包统一由 GitHub Actions 构建，日常使用不在本机重复打包。npm run build:native 与 npm run package 是原生构建入口，发布时由 CI 执行；npm run build 使用 Docker 单独构建手机与桌面前端。

### 历史阅读与任务操作

Windows 版可以向官方确认的本机聊天发送文字。聊天内点“新建聊天”以当前聊天为来源；首页新建先选择来源聊天，再选择其官方项目。创建只提交一次，正式聊天 ID 返回后继续确认首轮，结果不明时不会再次创建。忙时文字由官方追加消息入口处理，不表示已开放队列管理。

图片发送、队列修改/立即执行、停止、异常继续、设置、目标、审批和问题回复仍关闭，请在官方 Codex 完成。文字/图片草稿、语音听写、用量与通知保留。已连接页面在官方会话文件写入时推送更新，并定期核对桌面状态。首轮尚未生成会话文件时每 2 秒读取一次；只读页面每 5 秒检查已保存历史。首页仍展示本机历史，不按目录猜项目或执行归属。

“结果待确认”表示此前操作可能已经执行。先在桌面核对，再选择“结束等待”；此操作不会撤销或重发任务。刷新、重启服务或改写内容不会自动重发。

从有问题的旧版本升级：先停止手机写入，在桌面确认未决请求，只退出旧手机服务，再安装完整新版；官方 Codex 和已有任务不需要退出。首次切换不依赖旧更新器。旧记录不会被接管，用户聊天和草稿不清理。若旧页面写入提示需要升级，保留草稿后刷新。新更新器只自动启动或回退到声明新连接边界的运行包。

另一台电脑已有的重复/打不开条目，需要核对 source、hostId、threadId 和真实内容；本程序不会修改官方数据库、合并聊天或删除 rollout。

## 接入方式

### 在 VPS 部署云连接

在一台 Linux VPS 上用 Docker Compose 部署手机 PWA 和 Rust 中转。给手机网页准备一个域名，将 DNS 指向 VPS，并开放 TCP 80 和 443。

```sh
cp deploy/relay/.env.example deploy/relay/.env
```

把域名填入 `deploy/relay/.env`，然后从仓库根目录运行以下命令。Caddy 自动申请 HTTPS 证书，并把 `/relay/` 交给容器内的 Rust 中转。

```sh
docker compose --env-file deploy/relay/.env -f deploy/relay/compose.yaml up -d --build
```

1. 手机打开网页，点“用通行密钥创建账号”，按系统提示确认。账号会在确认后自动创建并登录。已有通行密钥可点“用通行密钥登录”。
2. 电脑打开 Codex Mobile，点“配置云连接”，在“设置 → 连接与维护 → 云连接设置”填写自己部署的手机网页 HTTPS 地址，保存后再点“手机扫码连接”。程序不提供默认中转服务器；未配置或清空地址时，云连接关闭。电脑名称留空时使用“Codex 电脑”，也可以填写便于自己识别的名称。
3. 从已登录的手机网页点“添加电脑”扫码，扫描后自动连接。二维码 3 分钟内有效，供一次配对使用。
4. 日常打开沿用 30 天登录会话。可在项目页顶部切换电脑并查看状态。添加其他电脑时逐台扫码。已提交的任务继续在原电脑执行，桌面可撤销单台手机的配对。

升级会保留此前保存的云连接配置。若不再使用原服务器，请在“云连接设置”清空手机网页地址并保存；之后扫码不会自动恢复旧地址。

打开电脑列表时，顶部显示手机到中转服务器的 HTTP 往返延迟。已配对且在线的电脑各自显示手机经中转往返到该电脑的时间。电脑读数从加密握手完成后开始计时。关闭列表或切至后台后停止测量。

已有账号和电脑保留原来归属。旧网页登录密钥和旧版扫码登录入口位于“其他登录方式”。新用户用系统保存的通行密钥恢复账号。清除站点数据后，电脑列表会随账号恢复，在这台手机重新扫码即可恢复加密配对。

VPS 的 `relay-data` 数据卷保存账号、登录会话、公钥凭证和各账号的电脑列表。新电脑首次扫码会登记到当前登录的账号，使用单独的接入凭证。Noise 配对凭证与电脑登记凭证独立，手机的配对私钥和草稿保存在本机。聊天内容由桌面端提供。

电脑和手机都主动连接 VPS，无需对公网开放电脑的 4319 端口。只用云连接时，可以在桌面“设置 → 连接与维护 → 服务设置”选择“仅本机”。电脑的固定身份和手机授权保存在该电脑的用户数据目录。中转重启后桌面自动重新登记。

手机从配对码取得桌面公钥，使用 Noise IK 建立端到端会话。普通请求、SSE、图片和文件都通过加密会话传输。中转保留当前连接的路由，能看到设备标识、连接时间和流量大小。手机网页和中转部署在同一台 VPS，网页发布权限属于信任边界。能替换网页代码的人可以改变浏览器中的加密行为。

桌面和手机都保持到 VPS 的 SSE 下行流，上行通过 HTTPS POST 批量提交二进制密文。SSE 将密文封装为 Base64 文本。使用 HTTP/2 时，SSE 和 POST 可以复用同一条网络连接。VPS 按桌面和手机会话路由，桌面桥接将认证后的请求交给现有聊天 API。普通请求、实时流和附件共享当前电脑的加密连接。连接中断后，手机重新进行 Noise 握手，打开的聊天通过新连接获取快照。

从旧云中转升级时，一并更新桌面客户端和 VPS 上的 `relay`、`web` 镜像。已有账号可继续登录，首次使用的人可以直接在手机网页用通行密钥注册后再扫码。

### Codex 用量

点击“Codex 用量”进入概览、每日、模型与对话页。右滑和顶部返回均回到进入前的页面：从列表进入返回列表，从聊天“更多 → 本对话用量”进入返回原聊天；用量列表中的对话明细先返回用量列表。同一页面会话内再次进入保留上次栏目、时间范围、搜索及阅读位置，全局和各聊天的用量状态分别保存。支持今天、近 7 天、近 30 天、全部时间，日期按手机浏览器时区划分。全部数字可直接查看精确整数，对话支持标题搜索和分页，子对话独立统计。

服务只读 `CODEX_HOME`（默认 `~/.codex`）中的状态库、会话和归档记录，按可核验的累计增量去重，按调用时记录的模型统计。缓存、推理是明细子项，不重复计入总量；缺失字段显示“未记录”。首条存在无法归属的历史基数、记录缺失或格式不兼容时显示数据覆盖说明，状态库汇总不会被补进主数字。

首次打开时建立本地索引并显示进度，随后只读取追加或变化的来源。页面可见时每 10 秒刷新，离开或进入后台后停止。用量账本保存到服务数据目录的 `usage.sqlite`（默认 `~/.codex-mobile/usage.sqlite`），只保留用量及必要归属信息；已导入的用量在源文件缺失后继续保留。接口沿用配对认证，不返回原始消息、密钥或文件路径。此统计表示本机已核验记录，不等同于账号跨设备账单。

### 本机数据与运行边界

历史 SQLite 和 rollout 只读，格式不受支持时显示错误。手机服务退出不退出官方 Codex；关闭窗口仍驻留托盘。桌面服务、官方运行时实例和手机连接各自独立，不复用其他桌面启动的工具环境。

| 变量 | 用途 |
| --- | --- |
| CODEX_HOME | 官方 Codex 实际数据目录 |
| CODEX_MOBILE_HOME | Mobile 配对、图片、用量、操作记录与更新目录，默认 ~/.codex-mobile |
| CODEX_MOBILE_HOST | 监听 IP，默认 0.0.0.0 |
| CODEX_MOBILE_PORT | 手机服务端口，默认 4319 |
| CODEX_MOBILE_PUBLIC_URL | 通知订阅缺少 Origin 时的地址 |
| CODEX_MOBILE_RUNTIME_DIRECTORY | Mobile 连接记录目录 |

手机以 390×844 和 844×390 浏览器视口验收，适配安全区、键盘和减少动态效果；浏览器模拟不等于 iPhone 实机验证。文字/上下文草稿保存在当前标签页 sessionStorage，图片引用及未决操作 ID 在 localStorage 按电脑隔离。恢复网络只补读状态。

消息中引用且通过授权检查的本机文件可以预览：HTML 隔离显示，Markdown/代码按 UTF-8 读取（最多 5MB），图片与音视频使用浏览器展示。PDF 与 Office 只显示文字。聊天与附件不进入离线缓存。

局域网直连、Tailscale 或自有 HTTPS 代理继续可用；PWA 安装和通知需要 HTTPS。连接密钥保存于 .codex-mobile/access-key，直到主动轮换；登录会话有效期 7 天，服务重启保留。

## iOS 网页 App 与通知

在 iPhone Safari 中通过 HTTPS 打开页面，选择“添加到主屏幕”，再从主屏幕打开。页面使用 viewport-fit、四边安全区和 visualViewport 适配刘海、Home 指示条、横屏及键盘；项目列表底部保留 Home 指示条空间，切换聊天会按对应草稿恢复输入框高度。PNG 图标由现有 public/icon.svg 派生。

手机设置、目标、模型、权限、上下文和委派面板使用统一的原生 dialog，以 300ms 进入、200ms 退出，支持拖动顶部抓手关闭。等待键盘退出时立即显示可取消的遮罩；关闭完成后才恢复输入焦点。聊天横向导航保留浏览器滚动吸附；历史页方向过渡和输入区切换采用短动效，流式正文不重复入场。图标触碰时不新增灰色底，保留按压与可见键盘焦点反馈；系统“减少动态效果”下保留轻微透明度反馈。

按当前交互要求屏蔽页面双指缩放和双击放大，保留单指滚动、文本选中和输入。输入字号至少 16px，避免 iPhone 聚焦时自动放大；系统辅助缩放由设备设置管理。

iPhone 键盘上方的上一项／下一项和完成按钮由 iOS WebKit 提供，当前网页 App 无法通过页面样式或替换输入标签强制隐藏。

iOS 16.4 或更新版本的主屏幕网页 App 支持系统推送。在项目列表点击顶部设置，或在聊天中打开“更多 → 对话设置”，开启“所有对话通知”并允许系统通知，可点击“发送测试通知”确认手机接收情况。一次开启覆盖所有本机 Codex 对话，自动包含新建对话，无需逐条设置。任务完成或失败时通知；历史完成记录、逐条输出和手动停止不推送。此前已开启的单对话订阅会升级为全局订阅，无需重新授权。

推送密钥与订阅保存在用户目录 .codex-mobile 下。关闭网页后，电脑端仍每两秒读取新完成或失败的任务摘要，通过浏览器推送服务通知手机，不依赖当前打开的聊天。电脑与 Codex 桌面端需保持运行，网络需要能访问 Apple 的推送服务；通知会等待 Codex 保存任务状态。退出当前设备或关闭全局开关会撤销该设备的通知；重启服务保留订阅和未过期的登录会话。

主屏幕安装、系统授权、锁屏通知、实体相机、Safari 麦克风和 iPhone 键盘需要实机确认，桌面 Chromium 的尺寸模拟不能替代。

当前是多设备配对入口，没有按用户或聊天隔离权限。普通网络地址只显示登录页；二维码只携带连接密钥，持有密钥的设备可以访问这台电脑全部本地 Codex 聊天。网页地址中的 thread 参数仅指定默认打开的聊天。

电脑浏览器和手机浏览器都打开聊天网页，配对管理统一放在桌面程序。手机通过域名或内网地址打开后使用连接密钥登录；已配对的手机浏览器可以直接进入聊天，界面的“断开此浏览器”会撤销该浏览器当前会话，不影响其他已配对设备。

## 语音输入

点击底部输入区的麦克风开始中文语音识别，启动中再次点击可取消，听写时可点击停止。识别文字追加到当前草稿，原有文字保留；结束后可以检查、修改，再点击发送。

文本输入始终可用，手动键入会立即取消本次语音，已识别的草稿保留，迟到结果不会覆盖手动修改。语音进行中暂停发送；切换聊天、退出登录或页面进入后台时会取消识别。

启动时最多等待 15 秒；收到启动回调或识别结果后进入正常听写，听写本身没有时长限制。停止后若连续 5 秒没有新结果或结束确认，会退出等待并显示提示，当前草稿继续保留。

该功能使用浏览器的 SpeechRecognition / webkitSpeechRecognition，音频由浏览器语音服务处理，桥接服务只接收你确认发送的文字。Chrome 的语音识别通常需要联网，浏览器支持和麦克风权限会影响可用性。

电脑 localhost 可作为开发入口。手机的 HTTP 局域网地址可能不允许页面语音识别，建议通过 HTTPS 打开；识别接口不可用或权限受限时，页面会给出提示，仍可使用手机键盘自带的麦克风输入。

## 技术栈

手机网页使用 Vue、Vite、md-editor-v3、qrcode.vue 和 Element Plus 图标。DOMPurify 清理 Markdown 渲染后的 HTML，qr-scanner 识别配对二维码。Rust 桥接复用 Codex 桌面的 `list_projects` 和 `create_thread`，并通过 Web Push 发送 iOS 后台通知。

## 验证

日常构建和通用验证使用 Docker Desktop 的 Linux 容器模式，只需 Docker 与 Node.js 24，无需在宿主安装 Rust：

```sh
npm run build
npm test
```

`build` 将手机与桌面前端导出到 `dist/`、`desktop-dist/`。`test` 在容器内完成两端前端构建、版本检查、网页测试、Rust/relay 测试及 fmt、check、clippy；测试每次执行，依赖和编译缓存复用。Rust 检查覆盖桥接与中转，Windows 命名管道、系统集成和桌面安装包仍由对应平台的原生验证负责。

容器不会挂载宿主项目的 `target`、`.local` 或个人目录，源码按 `.dockerignore` 白名单传入。缓存保存在 Docker 数据盘，由 BuildKit 的垃圾回收管理；切换 Docker 不会自动清除以前的本机编译缓存。Docker Desktop 可在设置中调整数据盘位置和构建缓存保留量。

原生 CI、平台调试使用以下显式命令：

```sh
npm run test:native
npm run test:relay
npm run build:web
npm run check:native
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
```

测试使用隔离数据。模拟协议与构建通过不能放行官方共享控制；Windows、macOS 各自完成官方权限、工具和生命周期验收后才能恢复相应能力。

## 自动打包与发布

[GitHub Actions](https://github.com/J-Smile/codex-mobile/actions) 在推送版本标签、提交 PR 或手动触发时，使用 Windows x64 与 macOS ARM64 运行器测试并打包。普通构建保存为 Artifacts，保留 7 天；单独推送源码到 main 不重复打安装包。

本机完成首次安装后，后续流程为“提交源码 → GitHub 编译打包 → GitHub Release → 桌面拉取更新”，无需在本地重新编译安装包。

1. 准备新版本时执行 `npm run release:version -- 0.3.20`（示例，实际版本必须高于已发布版本）。这只同步 package.json、npm 锁文件、Cargo.toml、Cargo.lock 与 Tauri 配置中的版本，不运行编译，也不提交或推送代码。
2. 提交并推送本次源码。在 [Build and release](https://github.com/J-Smile/codex-mobile/actions/workflows/release.yml) 中选择 **Run workflow**，选择包含修改的分支，勾选 **publish** 后运行。两平台测试、打包通过后，工作流以该次提交创建版本标签并发布正式 Release。也可以推送与源码版本一致的标签触发发布。日常发布优先从 `main` 手动运行，默认分支成功打包后保存可供后续版本和标签复用的 Rust 依赖缓存。
3. 桌面每 15 分钟检查公开的正式 Release，也可手动检查，无需配置 token。发现更高版本后下载 CI 生成的 ZIP、验证 SHA-256，并切换到新版。电脑只下载和运行成品，不执行 npm、Cargo 或 C++ 编译。

检查后可以展开“版本更新内容”，查看 GitHub Release 的版本号、发布日期与更新说明；已经是最新版时也可查看。手动准备好更新后，“安装 v版本号 并重启”会切换到下载的新版本。

CI 开始时校验所有版本号和发布标签。安装程序、免安装 ZIP 和 SHA-256 文件全部上传完成后，Release 才正式可见。已发布版本不覆盖；需要修复时提高版本号再发布。未勾选 publish 的分支手动构建只生成 Artifacts，桌面不会安装这些构建。

GitHub 构建与发布使用工作流自带的 GITHUB_TOKEN，无需把本机 token 上传为仓库 Secret。内置更新器默认匿名读取公开 Release，可选的只读 token 只保存在本机；两者用途独立，真实凭据和本机数据不进入公开仓库。

npm run package 只复制桌面程序、Rust 组件、手机构建资源和 README，在隔离数据目录启动包内 Rust HTTP 服务，检查网页资源与认证。个人历史、密钥、浏览器资料和本地配置不进入发布包。CI 的编译与隔离测试不代替 Windows/macOS 桌面和真实手机的实机验收。

当前页面通过 SSE 接收已保存历史的快照，每 5 秒检查变化；读取失败时保留已显示内容并提示错误，不自动恢复或执行任务。系统减少动态效果时取消位移和缩放。
